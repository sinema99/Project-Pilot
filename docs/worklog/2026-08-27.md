## New scenes / scripts

- **`scenes/Hub.tscn`** — standalone scene for the hub: `Node3D` root "Hub" + `HUB_blockout`
  instance + `DirectionalLight3D` + `WorldEnvironment` using the EXR panorama sky. No player
  in this scene (it's for viewing/iterating the map itself).
- **`scripts/hub_import.gd`** — `EditorScenePostImport` script wired into
  `assets/HUB_blockout.glb.import` via `import_script/path`. On every (re)import it walks the
  scene and, per `MeshInstance3D`:
  - `create_trimesh_collision()` → solid static concave collision (floor, walls, ramps).
  - sets every surface material `cull_mode = CULL_DISABLED` → polys visible from both sides.
  - if Blender exported no material, assigns a `StandardMaterial3D` with
    `albedo_color = (0.45, 0.45, 0.45)` (neutral greybox; pure white was blowing out).
  All three regenerate automatically on each re-export — no manual scene edits needed.

  - `DirectionalLight3D.light_energy = 0.15`

## `scenes/player.tscn` + `scripts/player.gd` changes

- **Camera no longer clips through walls.** `Camera3D` is now a child of a new `SpringArm3D`
  under `CameraPivot/CameraPitch` (both at identity transform — SpringArm3D casts along +Z,
  which is already where the camera sat). Arm: `spring_length = 4.0`, `margin = 0.1`, sphere
  `shape` radius `0.3`. `player.gd` updated the camera node path, added a `spring_arm` ref, and
  calls `spring_arm.add_excluded_object(get_rid())` in `_ready()` so the arm ignores the
  player's own body.
  - Dead end tried first: rotating the arm/camera 180° — collapsed the arm to zero length
    (first-person view). SpringArm3D casts +Z, so no rotation is correct.
- **Jump height doubled.** `JUMP_VELOCITY = 4.5 → 6.36` (height ∝ v²/2g, so ×√2 velocity = ×2 peak).
