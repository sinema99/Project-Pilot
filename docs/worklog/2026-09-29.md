# Worklog — 2026-09-29

**Window mode and resolution actually apply — grilled, specced, built.** See
[specs/settings.md](../specs/settings.md), "Display Modes". Not yet played.

## What the user said

"i want to be able to change the resolution and put the game in windowed, or full screen, or
borderless. lets implement that. i know in the settings its already there, but it doesnt work"

## Decisions (grilled)

1. BORDERLESS = borderless fullscreen.
2. In BORDERLESS / FULLSCREEN, RESOLUTION = 3D render resolution, stretched; stacks with RENDER
   SCALE. UI stays native.
3. WINDOWED re-centres on every change; a size that does not fit the desktop maximizes.
4. Saved display settings apply on boot everywhere, editor included.
5. First launch (and RESET TO DEFAULTS) = WINDOWED 1920x1080.
6. EXCLUSIVE renamed FULLSCREEN; old saves migrate.
7. The fifteen-second keep/revert confirm stays.

## Why it did not work

BORDERLESS was a frameless window, not fullscreen; RESOLUTION only called `window_set_size()`,
which fullscreen ignores; changing mode never re-applied size or position; and the editor skipped
both on boot, so relaunches looked unsaved.

## What shipped

- `scripts/settings.gd`: WINDOW MODE, RESOLUTION and RENDER SCALE share one `_apply_display()`;
  size/centre deferred a frame (Windows restores the old rect after leaving fullscreen); static
  `window_fits()` and `scale_3d()`; `exclusive` → `fullscreen` in `sanitise()`; editor boot
  exemption and native-resolution default removed.
- `project.godot`: `window_width_override` / `window_height_override` removed.
- `tests/test_settings.gd`: section 7, nine tests. Suite: 810 tests pass.

## Checked in the real game

Launched non-headless with each mode written to `settings.cfg` (the user's own file backed up
and restored), reading back mode / size / position / 3D scale on the 2560x1440 monitor:
no file → 1920x1080 centred; windowed 720p → centred; windowed 1440p → maximized 2560x1377;
borderless 720p → fullscreen, 0.5 scale; fullscreen 1080p → 0.75; old `exclusive` → fullscreen.
Runtime switching fullscreen → windowed → maximized → windowed 1080p and RENDER SCALE 50% all
landed. The settings screen itself was not clicked through — the confirm countdown is untested
by hand.

## Departure

A maximized fallback window renders at window size, not above it (`scale_3d()` caps at 1), so
"windowed 2560x1440" renders at 2560x1377.

## First play: "nothing happened"

"i just tried changing the resolution and i tried to change from windowed to fullscreen and both
times, nothing happened." The game log (`user://logs/godot.log`) showed Godot rejecting every
call: the game was embedded in the editor's Game tab, which only does windowed and cannot be
resized or moved. `settings.cfg` had saved the choice, so the settings path itself worked.

Fix for the user: Game tab → ⋮ → uncheck *Embed Game on Next Play*. Fix in the game: a note under
DISPLAY when `Engine.is_embedded_in_editor()`, no window calls and no revert countdown while
embedded. Checked by forcing the flag and screenshotting the settings screen; suite passes.
See specs/settings.md, "Embedded In The Editor".
