# 2026-10-15

## Intro_Movie

Spec: [specs/intro-movie.md](../specs/intro-movie.md). Grilled with the user. `res://Intro_Movie.tscn` (root
`Intro_Movie`, `scripts/cutscene/intro_movie.gd`) plays the four live shots back to back so the joins can be
judged: intro space -> cockpit -> descent -> flyover, ~43 s, hard cuts (`cut` export -> FADE, `fade_time`
0.3 s), holds the flyover's last frame. R restart, Esc quit, Right / Left skip, `start_shot` export. No overlay.
Open it and press F6; the main scene is still trial.tscn. The shot scenes are untouched.

- Every shot is instanced once and parked in its own non-drawing SubViewport (own world). Going live =
  reparent into the movie, processing on, the shot's own `_input` off, its camera made current, `restart()`.
- Startup shows each shot live for 4 frames under a black cover (~2 s) so its `_ready` and first window
  draws are paid before the movie starts. Warming in drawing SubViewports was tried first and left a
  34-39 ms frame at every cut; warming in the window brought the cuts to 14 / 10 / 26 ms (median frame ~7 ms).
- `Storm` fog is shared shader globals that `_exit_tree` switches off, so the movie re-applies the live shot's
  storms (or sets `storm_fog` 0) every time a shot goes live.
- Tests: `tests/test_intro_movie.gd` green. Suite: 1209 tests, the only failures are the 2 known ones in
  test_ichi_parked_ship. Probe: `tests/_probe_intro_movie.gd` (windowed, prints frame times at each cut).
- Seen, not fixed: cockpit's WARNING pop logs "Invalid polygon data, triangulation failed"
  (`holo_display.gd:272`) standalone too.
